# 02 · 威胁模型

## 1. 资产

- 文件明文内容。
- 主口令、导出口令、备份口令。
- RSA 私钥、VMK、fileKEK、DEK。
- 密文完整性与分块顺序。
- 清单、RSA 签名、签名者证书与信任关系。
- 审计记录的可用性与完整性（部分保护）。

## 2. 攻击者

| 编号 | 攻击者 | 能力 |
| --- | --- | --- |
| A1 | 离线存储攻击者 | 读取/复制 IndexedDB、导出的 `.sfv`、`.sfkey`、`.sfbackup` |
| A2 | 主动篡改者 | 修改密文、容器头、签名、分块顺序、截断容器 |
| A3 | 恶意容器作者 | 构造畸形头部、超大 KDF 参数、未知算法、重复键 |
| A4 | 运行时攻击者 | XSS、恶意浏览器扩展、被攻破的浏览器读取解锁期间内存 |
| A5 | 网络攻击者 | 本项目无网络传输，不适用 |
| A6 | 已失陷终端 | 键盘记录器、内存取证、物理访问、OS 后门——超出范围 |

## 3. 信任边界

- **可信**：浏览器 WebCrypto 实现、解锁后的用户设备、React 应用自身代码、用户输入的当前口令。
- **不可信**：IndexedDB 内容、导入的 `.sfv`/`.sfkey`/`.sfbackup`、未知签名者证书、文件名/MIME。
- **无服务端**：不存在服务器信任边界；所有密码学在本机完成。
- **未解锁状态**：密钥不可用；攻击者拿到 IDB 只能离线猜口令。

## 4. 安全目标

1. **静态机密性**：IDB/导出文件中没有明文内容或明文私钥。
2. **密文完整性**：任意 bit 翻转、分块重排、跨文件搬块、截断都能检测。
3. **认证性**：只有信任证书对应的 RSA 私钥能生成有效签名；头部字段不可被替换。
4. **口令错误可检测**：错误口令在 KCV 阶段失败，不产生明文。
5. **密钥可恢复**：备份/导出可在新浏览器恢复，同时不降低到明文保存。
6. **流程安全**：先验签后解密；失败不落盘；审计可追溯（本机）。

## 5. 攻击与控制

| 攻击 | 控制 | 残余风险 |
| --- | --- | --- |
| 读取 IDB/导出容器 | AES-GCM 加密；主口令经 PBKDF2/scrypt；私钥仅以包装形式存储 | 弱口令可离线暴力破解；KCV 提供校验 oracle |
| 翻转密文 bit | GCM tag 128 位；AAD 绑定 fileId/index/len/count/nonce | 无（除密码学实现缺陷） |
| 重排/跨文件搬块/截断 | AAD 绑定位置与 fileId；签名清单覆盖 chunkCount/size；容器总长度校验 | 无 |
| 修改头部字段/算法降级 | 规范化 JSON + 逐字节对比；全字段签名；算法允许列表 | 无（除非私钥泄露） |
| 用自己的证书与签名替换 | 信任库固定 SHA-256 指纹；证书主题/序列/指纹与清单比对 | 用户盲目点击“信任”会接受；TOFU 固有限制 |
| 替换整个容器为重放的旧容器 | 签名仍有效 | **无抗回滚/新鲜性**；需要外部版本计数器 |
| 伪造签名 | RSA-3072 PKCS#1 v1.5 + SHA-256；签名长度/算法校验 | 依赖 RSA/哈希安全性与实现 |
| 错误口令 | KCV 常数时间比较；失败不进入解密 | 攻击者可离线跑 KDF 猜测 |
| 恶意容器 DoS | zod 严格 schema；header ≤1 MiB；KDF 参数上限；chunk 数量/大小上限；安全解析 | 浏览器仍可能受大文件/配额影响 |
| 窃取私钥/备份文件 | 独立强口令 + PBKDF2 600k + AES-256-GCM；KCV 精确报错 | 备份口令弱/泄露则可离线破解 |
| XSS/恶意扩展 | React 默认转义、无 `dangerouslySetInnerHTML`、最小依赖；建议 CSP | 解锁期间可窃取 CryptoKey/明文；超出纯前端防护 |
| 私钥/证书被本地替换 | 密钥环 HMAC 完整性（KCVKey 派生自口令）；私钥/证书匹配自检 | 攻击者可删除/拒绝服务，但无法在不知道口令时伪造 |
| 审计被本地删除/改写 | 记录元数据；可导出 | 无哈希链/远程存储；本机攻击者可篡改 |
| 清除站点数据 | 用户手册 + 备份/导出 | 未备份则数据丢失 |
| 多标签页并发 | pending 清理只处理 15 分钟前记录；最终写入 commit | 极端并发/同一文件操作可能冲突 |

## 6. 明确的非目标

- 抵抗已失陷操作系统/浏览器、键盘记录器、内存取证。
- 安全删除（IndexedDB、浏览器缓存、SSD 磨损均衡）。
- 元数据保密（文件名、大小、MIME、时间）。
- 抗回滚/新鲜性、可信时间戳。
- 多用户权限、共享、撤销、服务端访问控制。
- 真实 PKI/CA、证书吊销（CRL/OCSP）、身份核验。
- 侧信道/故障注入/供应链攻击的完整防护。
- 对恶意文件内容的沙箱执行（本系统只存储/下载，不渲染/执行）。

## 7. 典型攻击推演

**A1 拿到 IndexedDB**

- 得到：AES-GCM 分块、`wrappedDek`、`fileSalt`、KDF 参数/KCV、加密后的 PKCS#8、证书、明文文件名/大小。
- 不能直接得到明文或私钥；需要猜主口令，成本由 PBKDF2/scrypt 参数决定。
- 若口令弱或复用，可能被离线破解；KCV 使每次猜测的验证更快，但不改变 KDF 成本。

**A2 修改密文**

- 修改任意分块 → GCM tag 失败（`E_AUTH_TAG`），解密中止，无 Blob。
- 交换分块 → AAD 中 index 不匹配，GCM 失败。
- 把另一文件的块搬进来 → AAD 中 fileId 不匹配，GCM 失败。
- 截断 → 容器总长度/块数校验失败（`E_CONTAINER_PARSE`）。

**A3 修改头部/签名**

- 修改文件名、算法、KDF、wrappedDEK 等 → 规范化清单与签名不匹配（`E_SIGNATURE`）。
- 非规范编码/重复键 → 重新规范化后字节不一致（`E_NON_CANONICAL`）。
- 用自己的密钥重签 → 证书指纹不在信任库（`E_CERT_UNTRUSTED`），除非用户手动信任。
- 把另一文件的合法签名搬过来 → 签名覆盖的清单不同，验签失败。

**A4 解锁期间 XSS**

- 可读取 VMK、私钥 CryptoKey、当前明文、口令输入。
- 纯前端无法防御；报告将其列为范围外/残余风险，建议 CSP、最小依赖、独立浏览器配置文件。

## 8. 安全假设

- WebCrypto 的 AES-GCM/PBKDF2/HKDF/HMAC/RSA 实现正确且常数时间。
- `crypto.getRandomValues` 是 CSPRNG；IV/DEK/salt 无重用。
- 用户选择足够强的口令，并离线保存备份。
- 用户通过可信渠道核对首次信任证书的完整指纹。
- 浏览器/操作系统在解锁期间未被攻陷。
