# 08 · 现场演示脚本（5–8 分钟）

## 0. 演示前检查

- [ ] `npm run build` 成功；`npm run preview -- --host 127.0.0.1 --port 4173` 已启动。
- [ ] Chrome/Edge 打开 `http://127.0.0.1:4173`，确认是 localhost（安全上下文）。
- [ ] 准备演示文件：`demo-small.txt`、`demo-image.png`、`demo-100mb.bin`（可用脚本生成）。
- [ ] 关闭无关标签页；使用独立浏览器 profile，避免旧数据干扰。
- [ ] 准备两个已导出的文件作为 fallback：`demo.sfv`、`tampered.sfv`。
- [ ] 记住演示口令（不要用真实口令）；演示结束关闭浏览器/清除站点数据。
- [ ] 打开 `artifacts/benchmark-report.md` 备用，防止现场性能抖动。

## 1. 时间线

### 0:00–0:40 开场

- “这是一个纯前端安全文件存储系统：加密、完整性、签名、证书、密钥生命周期全部在浏览器内完成，没有后端。”
- 指出四个关键设计：分块 AES-GCM、PBKDF2/scrypt + HKDF、RSA 签名规范化清单、先验签后解密。
- 打开文件库页面。

### 0:40–1:40 创建保管库

1. 点击“创建保管库”，显示名称填“答辩演示”，设置主口令（≥12 位），选择 PBKDF2 600k。
2. 勾选风险确认，创建。
3. 说明：生成 RSA-3072 + 自签名 X.509；PBKDF2 600k 在本机约 0.2 秒；私钥被 AES-GCM 包装后存 IndexedDB。
4. 创建后指向顶部证书指纹与 KDF 标签。

### 1:40–2:40 拖拽加密

1. 从资源管理器拖入 3 个文件（含 100 MB）。
2. 加密设置：AES-256-GCM、SHA-256；指出签名强制开启、KDF 档位。
3. 开始加密；展示逐文件进度、分块哈希/加密、签名、耗时。
4. 完成后指向文件库：算法标签、哈希标签、签名者指纹、来源。

### 2:40–3:40 正确口令解密 + 验证报告

1. 选择小文件 → 解密。
2. 先展示“校验证书 → 验证签名”通过，再输入口令。
3. 解密成功，展示报告：证书、签名、口令 KCV、解包 DEK、AES-GCM、内容哈希、生成下载。
4. 强调：失败不会生成下载文件；报告可复制 Markdown/JSON。

### 3:40–4:20 错误口令

1. 再次解密 → 输入错误口令。
2. 展示 `E_WRONG_PASSWORD`、红色“已阻止输出明文”；没有下载。
3. 说明 KCV：HMAC 校验值让错误口令精确失败，而不是笼统的“解密失败”；同时说明它给离线攻击者一个校验 oracle，抗暴力仍靠 KDF。

### 4:20–5:20 现场篡改

1. 侧边栏“篡改实验室”。
2. 选择目标文件 → “篡改密文 1 字节” → 输入正确口令 → 运行。
3. 展示“符合预期”：实际阶段“解密内容”、`E_AUTH_TAG`；解释 AAD 绑定 fileId/index/长度。
4. 改为“替换签名” → 运行 → `E_SIGNATURE`（不进入解密）。
5. 可选：改为“替换签名者证书” → `E_CERT_UNTRUSTED`；解释 TOFU 指纹固定。
6. 强调：所有篡改在内存副本上完成，原文件未被破坏；可导出被篡改 `.sfv`。

### 5:20–6:10 密钥管理

1. 密钥管理页：展示证书主题、序列号、有效期、SHA-256 指纹、信任库。
2. 点击“创建密钥备份”，输入主口令 + 独立备份口令，下载 `.sfbackup`。
3. 指出：备份不含文件内容；私钥只以 AEAD 包装形式存在；备份文件泄露 + 弱口令可离线破解。
4. 可展示“导出私钥 .sfkey”与“从备份/私钥恢复”入口（不一定要现场执行恢复，时间够可做）。

### 6:10–6:50 性能数据

1. 性能页展示已导出的 Markdown 或现场跑 1 MB。
2. 读出关键数字：
   - AES-256-GCM：约 0.8–0.9 GiB/s（1–10 MB）；
   - 100 MB 端到端加密约 1.23 s，解密约 1.16 s；
   - PBKDF2 600k 约 0.18 s；scrypt 2^17 约 0.64 s / 128 MiB；
   - RSA-3072 签名约 6.6 ms，验签约 0.1 ms。
3. 说明端到端不含 IDB/下载落盘；报告使用本机重跑数据。

### 6:50–7:40 安全局限

- SHA-1 已被实际碰撞（SHAttered），默认 SHA-256，签名摘要仍 SHA-256。
- 自签名证书 + TOFU 没有 CA/吊销；首次信任需核对完整指纹。
- JS 无法保证内存擦除；XSS/扩展可绕过。
- 文件名/大小等元数据明文。
- 无抗回滚：旧合法容器可重放。
- 安全删除不可保证（IndexedDB/SSD）。
- RSA PKCS#1 v1.5 vs PSS；本地时钟不可信。
- 审计日志本机可篡改。

### 7:40–8:00 收尾

- “系统满足题目的 AES、SHA、PBKDF2/scrypt、RSA 签名、四项密钥管理、拖拽、现场篡改与性能数据要求。”
- “所有失败路径都不产生明文；所有密钥操作都可审计。”
- 留下报告/文档链接。

## 2. 抗 AI 提问准备

**Q：为什么口令不能直接截断成密钥？**

A：口令熵低且长度可变，截断会丢失熵、造成大量口令映射到同一密钥；PBKDF2/scrypt 用完整 UTF-8 NFC 口令 + 随机 salt + 高成本迭代，抵抗离线暴力并避免相同口令产生相同密钥。

**Q：为什么用 PBKDF2 600k，不是 10k？**

A：600k 是 OWASP 2023 推荐量级；本机实测约 0.18 s，用户可接受，攻击者离线成本显著提高。低配可选 300k 或 scrypt；报告给出实测表。

**Q：AES-GCM 的 IV 怎么保证不重用？**

A：每文件独立随机 256-bit DEK；IV = 64-bit 随机 fileNonce + 32-bit 块计数器；同一 DEK 下 IV 唯一，单文件最多 2^32 块（本项目上限 4096）。

**Q：为什么签名清单而不是直接签密文？**

A：清单包含算法、KDF 参数、wrappedDEK、内容哈希、证书指纹；签名覆盖这些字段可阻止算法降级/参数替换。密文完整性由 GCM tag 保证，明文哈希再与签名清单比对，语义是“签名者认证的内容”。

**Q：为什么先验签后解密？**

A：避免在未认证的头部/参数上派生密钥或处理明文；签名失败时不接触明文、不产生输出。替换签名会停在 S2。

**Q：KCV 不是给攻击者一个 oracle 吗？**

A：是。KCV 让 UI 能精确区分“口令错误”和“数据损坏”，但攻击者本来就可以离线跑 KDF 猜测；KCV 只省去尝试解包的步骤，不降低 KDF 成本。决定性因素仍是口令强度与 KDF 参数。

**Q：自签名证书有什么用？**

A：它把公钥与身份/有效期绑定，并提供 SHA-256 指纹做本地信任固定（TOFU）。它不能证明真实身份、没有吊销；真实系统需要 CA/PKI。报告已列为安全局限。

**Q：篡改密文为什么不是签名先失败？**

A：密文不在 RSA 签名覆盖范围内；签名覆盖的是头部清单（含明文哈希）。密文完整性由 AES-GCM tag 与 AAD 保证。现场测试顺序：先验签通过，解密时 GCM 失败（`E_AUTH_TAG`）。

**Q：修改主口令会重新加密文件吗？**

A：不会。只解开并重包每个本地文件的 wrappedDEK，并重签清单；文件内容不变。导入的外部容器不重包，仍用原口令；已导出的 `.sfv` 也保留旧口令。

**Q：备份和导出私钥有什么区别？**

A：`.sfkey` 只含私钥+证书，导入时替换签名密钥；`.sfbackup` 含私钥、证书、信任库、显示名，用于新浏览器重建保管库。两者都用独立口令 + PBKDF2 600k + AES-256-GCM；都不含文件内容。

## 3. 故障 fallback

- 如果现场加密大文件太慢：用 10 MB 文件或展示已导出的性能报告。
- 如果拖拽被浏览器拦截：用 DropZone 的“选择文件”按钮（同样走加密流程）。
- 如果某一步失败：直接打开“篡改实验室”使用预导出 `.sfv` 和预置错误/篡改场景，报告仍可展示。
- 如果性能数据抖动：使用 `artifacts/benchmark-report.md` 的本机数据，并说明现场环境差异。
- 如果忘记演示口令：关闭无痕窗口重新创建；不要使用真实数据。

## 4. 演示结束清理

- 关闭浏览器/清除站点数据（演示保管库含测试密钥）。
- 不要提交 `artifacts/*.sfbackup`、`*.sfkey` 到公开仓库。
- 保留截图与 `benchmark-report.md` 作为报告证据。
